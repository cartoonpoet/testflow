### 절 배치와 번호

`3. 실행` 뒤, `자주 겪는 문제` 앞에 넣었다 — **실행해 보고 막힌 사람이 바로 만나는 자리**다.
뒤 절은 5·6·7 로 밀렸다. 본문이 번호로 가리키던 곳(`import 제약(1번)` 등)은 **절 번호가 아니라 제약 번호**라 영향 없음을 확인했고,
새로 추가한 상호참조(`4절 ①`, `2절 5번`)는 전부 실제 위치와 대조했다.

### 다른 절에 파급한 것

- **도입부**에 한 문단 추가 — "제약을 다 지켜도 실제 서비스에서는 안 도는 코드가 따로 있다 → 4절".
- **2절 5번(요소를 찾는 방법)** — `.nth(0)` 권장 문장을 **경고 notice 로 교체**하고, 코드 블록을 `❌ .nth(1)` / `✅ 맥락으로 좁히기` 대조로 바꿨다.
- **2절 2번(파일 1개)** — `test()` 를 여러 개 두면 **영상도 `test()` 마다 따로 생겨** 스텝 seek 가 어긋난다는 진짜 이유를 붙였다(`step-time.ts:34-38`).
  같은 자리에 "`test()` 가 하나도 없으면 노란 경고"(검증은 **경고**지 거부가 아니다 — `code-validation.ts:346-354`)도 정확히 적었다.
- **5절 자주 겪는 문제** — Q 2개 추가(버튼이 보이는데 타임아웃 / 에디터에 글자는 보이는데 저장 거부), 계정 3쌍 사례 추가.
- **7절 요령** — "녹화 산출물을 그대로 쓰지 마라(`fill()`·`.nth(N)`·이름·assert 0건)" 한 줄 추가.

## 3. ★ 프롬프트 블록 변경 — 항목 수와 길이를 어떻게 판단했나

**결론: 6항목 → 9항목. 1420자 / 30줄.** 후보 5개 중 3개만 새 항목으로 올렸다.

### 판단 근거

1. **"AI 가 지킬 수 있는 것"만 올렸다.** ③(`aria-hidden`)과 ⑥(첫 클릭)은 *진단* 지식이지 *작성 규칙*이 아니다 —
   프롬프트에 넣으면 "모달이 뜨면 …" 같은 조건문이 늘어날 뿐 코드 품질이 안 오른다. 대신 **⑨ "저장 뒤 expect"** 한 줄이
   두 함정을 동시에 막는다(모달 거부를 조기에 잡고, 통과로 기록되는 사고를 없앤다). **묶는 쪽**을 택했다.
2. **기존 항목에 얹을 수 있으면 새 번호를 만들지 않았다.** ④(데이터 이름)는 이미 **4번(값을 코드에 박지 마)** 과 같은 규칙이다 —
   항목을 늘리는 대신 4번을 그대로 뒀다. ②(iframe)와 ⑤(`.nth`)는 **둘 다 "순서·불안정 속성에 기대지 마라"** 라서 **8번 하나로 합쳤다.**
3. **번호를 1~6 그대로 둔 이유.** 본문이 "import 제약(1번)" 처럼 번호로 가리키고, 2절의 제약 6가지와 1:1로 붙어 있다.
   7~9 를 **뒤에 덧붙이고** 그 앞에 한 줄 구분선을 넣는 쪽이 가리킴을 안 깨뜨린다.
4. **구분선 문구를 사실로만 썼다** — "아래 3개는 **저장은 통과하지만** 실제 웹앱에서 자주 깨지는 것들이야."
   (1~6 이 전부 저장 시 거부되는 것은 **아니다** — 실제 검증기가 막는 것은 import·크기·파일명·첨부뿐이다. 거짓을 쓰지 않았다.)

### 길이를 숫자로 못 박았다 — 새 테스트 1건

프롬프트는 늘리고 싶은 압력이 계속 들어오는 자리라, "늘릴 수는 있지만 공짜가 아니다"를 테스트로 남겼다.

```
항목 수 ≤ 10 · 전체 길이 ≤ 1800자 · 번호가 1부터 빠짐없이 이어진다
```

지금 값은 **9항목 · 1420자**. 넘기고 싶으면 **기존 항목을 묶어서** 자리를 만들라고 주석에 적었다.

## 4. ★ 덤으로 고친 렌더 결함 — 굵게 안의 백틱이 화면에 그대로 나왔다

작업 중 스크린샷에서 발견했다. `InlineMd` 는 규칙 3개가 **교대(alternation)** 로만 붙어 있어 **중첩을 모른다.**

```
"**CKEditor 의 `change` 가 …**"   →  화면:  CKEditor 의 `change` 가 …     ← 백틱이 글자로 남는다
```

`content.ts` 머리말이 "`InlineMd` 가 모르는 문법을 쓰면 화면에 원문이 그대로 노출된다"고 못 박아 둔 바로 그 사고인데,
`content.spec.ts` 는 링크·이미지만 막고 있었다. 실제로 **본문 11곳**에서 새고 있었다(내가 새로 넣은 6곳 + **기존 5곳**).

- 전부 고쳤다 — 코드 칩을 굵게 **밖으로** 뺐다. 예: ``"**파일 1개 · `test()` 1개**"`` → ``"**파일 1개** · `test()` **1개**"``
- **재발 방지 테스트 1건**을 추가했다(`**…`…`…**` 금지).
- 렌더 검증: 본문·표·목차 전체에서 백틱 노출 **0건**.

## 8. 미검증 / 남은 것

   다른 스택에서도 성질(언어·순서·접근성 트리)은 같지만 **클래스 이름(`cke_wysiwyg_frame` 등)은 그 서비스 것**이다 — 본문에 실측 사례임을 밝혀 뒀다.
