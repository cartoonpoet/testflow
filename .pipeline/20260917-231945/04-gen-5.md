## 3. `total_steps` 증가 처리 · "대기 행 없음" 표현 설계

### 3.1 M 은 단조 증가다 (실측)

```
multi    : M 추이 = 0 → 2 → 3 → 5 → 9   · 단조 증가 = true
fail     : M 추이 = 0 → 1 → 6 → 8 → 9 → 10 · 단조 증가 = true
nostream : M 추이 = 0 → 2 → 10 → 11 → 13  · 단조 증가 = true
```

`lib/run-events.ts` 에 `monotonic(current, incoming)` 을 넣어 **`step.started` · `run.finished`
양쪽의 `totalSteps` 반영을 `Math.max` 로** 바꿨다. 근거: 재연결 재전송으로 **과거의 작은 값**이
뒤늦게 들어오면 M 이 되돌아가 보이고, 사용자에게는 "단계가 줄었다"로 읽힌다.
단위 테스트로 고정했다(§6 의 `★ M(총 단계 수)이 커져도 되돌아가지 않는다`).

요약바에는 코드 실행이 진행 중일 때만 **"총 단계 수는 실행하면서 확정됩니다"** 한 줄을 덧붙인다.
숫자가 갑자기 늘어나는 이유를 안 적으면 그것 자체가 오보로 읽힌다.

### 3.2 ★ 대기 행이 없다 — 무엇으로 대신했나

**문제가 하나 더 있었다(실측으로 발견).** 계획서는 "스텝 리스트는 도착한 행만 그린다"고 했지만,
라운드 1의 `applyRunEvent` 는 `step.started`·`step.finished` 를 **기존 배열 위에 `map`** 만 한다.
코드 실행은 `step_results` 가 시딩되지 않아 배열이 **빈 채로 시작**하므로,
그대로 두면 **실행이 끝날 때까지 "표시할 단계가 없습니다"만 보인다**(이벤트가 반영될 대상이 없다).

→ `applyRunEvent` 에 **없는 sequence 면 행을 새로 만들어 붙이는** 분기를 넣었다.
   **`detail.sourceType === "code"` 일 때만** 탄다 — 녹화 실행의 동작을 0으로 만들기 위해서다
   (회귀 방지 테스트로 고정했다).
   `step.started` 만 온 단계는 **임시 행**(`placeholderStep`)이고 `step.finished` 가 오면
   서버가 준 진짜 `StepResult` 로 통째 치환된다.

3-상태 중 **대기 행 자리에는 번호 없는 한 줄**을 둔다(번호를 지어내지 않는다):

```
⋯  다음 단계를 기다리는 중입니다
   코드 실행은 단계가 실행되면서 하나씩 나타납니다. 전체 단계 수는 미리 알 수 없습니다.
```

실행 중에만 나오고 끝나면 사라진다. 시안 토큰(`--color-wait` / `--color-wait-ink`) 그대로다.
안 두면 마지막 스텝이 끝난 직후 화면이 "다 끝났다"로 보인다(실제로는 다음 스텝을 찾는 중이다).
실측 행 수 추이(`awaiting` 행 1개 포함): `0 → 1 → 3 → 4 → 6 → 10 → 9`
— 마지막 `10 → 9` 는 `run.finished` 뒤 재조회로 `awaiting` 행이 빠진 것이다(스텝 행은 9로 불변).

`step_results.step_id` 는 **전량 NULL** 임을 API 응답으로 확인했다(§1.5 로그).
화면은 `step_id` 를 쓰지 않으므로 영향이 없다.

### 3.3 코드 실행의 `running` 문구가 다른 이유

임시 행에는 `actionType` 이 없다(`step.started` 이벤트에 그 필드가 없다).
그래서 코드 실행의 `running` 행만 **"실행 중입니다"**(동작 이름 없이)로 그린다.
`step.finished` 가 오면 매퍼가 만든 진짜 `actionType` 이 들어와 라운드 1 문구가 그대로 쓰인다
(`g5-multi-live-2.png` 에 `클릭 동작을 마쳤습니다` / `실행 중입니다` 가 함께 찍혔다).

## 9. 이슈 / 결정사항

### 이슈 1 — ★ 코드 실행의 스텝이 화면에 **하나도 안 쌓이는** 버그가 있었다 (발견, 수정함)

라운드 1의 `applyRunEvent` 는 `step.started`/`step.finished` 를 **기존 `detail.steps` 위에 `map`** 한다.
코드 실행은 `step_results` 가 시딩되지 않아 그 배열이 **빈 채로 시작**하므로, 이벤트가 아무 데도
반영되지 않고 화면은 실행이 끝날 때까지 "표시할 단계가 없습니다"에 머문다.
**계획서 Task 5.7 의 "도착한 행만 그린다"가 리듀서 변경 없이는 성립하지 않았다.**

**수정**: 없는 sequence 면 행을 새로 만들어 붙이고 sequence 로 정렬한다.
**`sourceType === "code"` 에서만** 탄다 — 녹화 경로의 동작을 0으로 만들기 위해서다.
회귀 방지 테스트(`★ 녹화 실행에는 행을 새로 만들지 않는다`)를 같이 넣었다.

### 이슈 2 — 코드 본문이 없는 시나리오를 열면 **콘솔에 404 가 한 줄 찍힌다**

`GET /api/scenarios/:id/code` 는 본문이 없으면 404 가 계약이다(04-gen-2). 화면은 그것을
`null`("아직 비었다")로 정상 처리하지만, **브라우저는 실패한 fetch 를 무조건 콘솔에 남긴다.**
`fetch` 로는 이것을 억제할 방법이 없다.

- 라운드 1 규율 "콘솔 에러 0건"과 어긋나므로 **숨기지 않고 기록한다.**
- 실행 현황 화면 · 시나리오 목록 · 빌더 · **녹화 전 구간은 콘솔 에러 0건**임을 따로 확인했다
  (§4 로그 · `probe404.mjs` 로 run 상세 페이지 HTTP 실패 0건).
- 없애려면 상세 응답에 `hasCode` 같은 플래그를 더해야 한다(API·contracts 변경).
  **이번 범위 밖**이라 하지 않았다. Gen-Phase 6 이 판단할 항목으로 남긴다.

### 결정 1 — 전환 오버레이는 **지연 표시**다 (최소 표시 시간이 아니다)

04-gen-4 전달사항은 "짧은 깜빡임을 견디는 **최소 표시 시간**(예: 300ms)"을 제안했다.
**반대로 했다 — 400ms 동안 이어질 때만 띄운다.** 근거: 0.1초짜리 전환을 300ms 동안 붙잡아 두면
"보이지도 않던 것"이 "잠깐 번쩍이는 것"이 된다. 사용자가 읽을 수 없는 신호는 오보에 가깝다.
**첫 프레임 전에는 지연 없이 즉시** 띄운다(캔버스가 비어 있어 깜빡일 대상이 없고,
그 구간이 최대 15초라 오히려 안 띄우면 "멈췄다"로 읽힌다).

### 결정 2 — `enabled` 가 false 가 돼도 소켓을 끊지 않는다

실행이 끝나면 SSE 가 상태를 종료로 바꾸고 `enabled` 가 false 가 된다. 그때 `wsUrl` 을 `null` 로
만들면 이펙트 정리가 소켓을 닫아 **`{t:"state", state:"ended"}` 를 못 받는다** → 배지가 안 뜬다.
그래서 `enabled` 는 **토큰 발급 쿼리만** 막고, 소켓은 서버가 `ended` 후 1.5초 linger 뒤
`close(1000)` 할 때까지 살려 둔다. 실측 `conn=closed & frame=true & phase=ended` 가 그 결과다.

### 결정 3 — 라이브 토큰 쿼리는 `staleTime: Infinity` · `gcTime: 0` · 자동 재시도 없음

토큰은 **1회용이고 키가 하나**라, 자동 재조회가 곧 "지금 붙어 있는 세션의 토큰 무효화"다.
그래서 자동 재시도·포커스 재조회·재연결 재조회를 전부 껐다. 회복은 **"다시 연결" 버튼**뿐이다
(04-gen-4 이슈 1 의 15초 초과 대기가 그 경로다). `gcTime: 0` 이라 화면을 떠나면 토큰이 캐시에 안 남는다.

### 결정 4 — 임시 스텝 행의 `id` 는 uuid 가 아니다

`live-<runId>-<sequence>` 형태다. React key 로만 쓰이고 서버로 돌아가지 않으며,
`step.finished` 가 오면 진짜 행으로 통째 치환된다. `RunDetail` 캐시는 zod 로 재파싱되지 않는다
(`lib/api.ts` 는 **응답**만 파싱한다). 이 사실을 `placeholderStep` 주석에 남겼다.

### 결정 5 — 목록에 열을 늘리지 않았다

`sourceType` 을 7번째 열로 만들지 않고 **시나리오 이름 옆 작은 태그**(`코드`/`녹화`)로 뒀다.
시안의 6열 구조가 계약에 가깝고, 열을 늘리면 `min-width: 820px` 과 반응형 숨김 규칙이 함께 흔들린다.
코드 시나리오는 `stepCount` 가 항상 0이라 부제도 `TC-… · 0개 스텝` → **`TC-… · 코드 실행`** 으로 바꿨다
(사실이지만 오해를 만드는 표기를 지웠다). 라벨은 contracts 의 `SCENARIO_SOURCE_TYPE_LABEL` 을 쓴다.

### 결정 6 — 목업을 "다시 만들지" 않았다

보여 줄 화면이 없을 때는 중립 안내 한 문장만 둔다. 녹화 실행에는
**"녹화 기반 실행은 실행 화면이 스트리밍되지 않습니다"** 를 그대로 적는다 — 있는 척하지 않는다.
실행 정보 kv 에도 코드 실행일 때만 **`콘솔·네트워크 로그 — 수집하지 않습니다`** 를 넣었다
(04-gen-3 전달 6번 · 04-gen-4 전달 11번).
