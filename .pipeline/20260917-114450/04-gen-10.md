## ★ 클릭 좌표 정확도 (배율별)

**27 케이스 = 배율 3종 × 표적 9개.** 표적은 fixture 의 절대 좌표(아이디/비밀번호/로그인/
확인 A·B·C/삭제 A·B·C)다. 측정은 두 층으로 했다.

**① 전송 좌표 오차** — 캔버스에 진짜 `mouse.down` 을 쏘고, `WebSocket.prototype.send` 를
가로채 **클라이언트가 실제로 보낸 `{t:'mouse'}` 의 x·y** 를 의도한 원격 좌표와 비교했다.
클릭 지점은 클라이언트 변환식과 **다른 방식**(기하학적 역함수)으로 계산한다 — 그래야 오차가 상쇄되지 않는다.

| 캔버스 배율 | canvas rect | 적중률(요소 안 착지) | 최대 오차 | **고장난 공식(`canvas.width`) 최대 오차** |
|---|---|---|---|---|
| **100%** | 1280.00×800.00 | **9/9** | **0.00 px** | 0.00 px |
| **70%** | 896.00×560.00 | **9/9** | **1.35 px** | **200.53 px** |
| **130%** | 1664.00×1040.00 | **9/9** | **0.54 px** | **200.53 px** |
| 합계 | | **27/27** | **1.35 px** | — |

- **적중 판정 기준**: 가장 작은 표적(버튼 90×32)의 절반이 16px 이다. 최대 오차 1.35px 는
  그 **1/11** 이므로 27건 전부 의도한 요소 안에 착지한다.
- **남은 1.35px 은 변환식 오차가 아니다.** DOM `MouseEvent.clientX` 가 **정수로 반올림**되기
  때문이다. 배율 0.7 에서 클라이언트 1px 오차는 원격에서 1/0.7 = 1.43px 로 확대된다.
  배율 100%(확대 없음)에서 오차가 **정확히 0.00** 인 것이 그 증거다.
- **음성 대조군**: 같은 클릭 데이터로 `rect.width` 대신 `canvas.width` 로 나눴다면
  **70%·130% 에서 최대 200.53px** 어긋난다(100%에서만 0). 04-gen-3 이 잡은 실패 모드와
  정확히 같은 모양이다. `frame.spec.ts` 에 이 대조군을 **단위 테스트로 못박았다.**

**② end-to-end 요소 적중 — 21/21.** 좌표가 맞는다는 것과 "의도한 요소가 눌렸다"는 것은 다르다.
그래서 배율 3종 × 버튼 7개(로그인·확인A/B/C·삭제A/B/C)를 클릭하고, **원격 브라우저가
만들어 낸 스텝의 Locator 가 의도한 요소를 가리키는지**를 확인했다. 판정 주체가 원격 쪽이라
클라이언트 계산과 독립적이다.

```
✅ 로그인   → {"by":"role","role":"button","name":"로그인"}
✅ 확인 A/B/C → {"by":"testid","value":"confirm-a" / "confirm-b" / "confirm-c"}
✅ 삭제 A/B/C → {"by":"role","name":"삭제","nth":0 / 1 / 2}
… 배율 100% / 70% / 130% 에서 각각 7건, 총 21/21 순서까지 일치
```

배율을 바꾸지 않았다면 100% 7건만 보고 통과라고 썼을 것이다. **배율 매트릭스가 실제로 검사한다.**

## 한글 IME (A안) 실제 입력 결과

**실제로 넣어 봤고, 들어갔다.** 다만 **정확도 정식 검증은 PoC-2 / Gen-Phase 12** 이며
여기서 한 것은 클라이언트 구현 확인이다.

| 입력 경로 | 보낸 메시지 | 원격에 들어간 값 |
|---|---|---|
| **조합 경로** — CDP `Input.imeSetComposition`(ㅎ→하→한→한그→한글) + commit | `{"t":"ime","kind":"commit","text":"한글"}` **1건** | `한글` |
| **조합 경로** (문장) | `{"t":"ime","kind":"commit","text":"안녕하세요"}` **1건** | `qa-tester안녕하세요` — 기존 값 뒤에 이어 붙음 |
| **무조합 삽입 경로** — `keyboard.insertText` (붙여넣기와 같은 모양) | `{"t":"ime","kind":"commit","text":"계약서를 검토합니다"}` **1건** | `계약서를 검토합니다` (공백 포함 그대로) |

- **자모 분리·중복·누락 없음.** 조합 중간 상태(ㅎ/하/한/한그)는 **네트워크를 건너지 않았다** —
  `commit` 1건만 나갔다. 원격에 남은 스텝도 `{"value":"계약서를 검토합니다"}` 로 온전하다.
- **영문·숫자는 키 경로로 간다.** `qa-tester` 9자는 `{t:'key'}` 로 나갔고(`isComposing` 분기),
  원격에서 정상적으로 `keydown` 이 발생해 fill 스텝이 만들어졌다.
- ⚠️ **한계 — 이건 "실사용자가 두벌식 키보드로 친 것"이 아니다.** 자동화 도구가 CDP 로
  조합 이벤트를 흉내 낸 것이다. 실제 Windows/macOS IME 의 조합 취소·재변환·한자 변환은
  **측정하지 않았다.** 그리고 `Input.insertText` 는 원격에서 `keydown` 을 발생시키지 않으므로
  (04-gen-3 이 적은 A안의 알려진 한계), keydown 의존 위젯에서 깨질 수 있다. **PoC-2 의 몫이다.**
- `IME_BRIDGE_MODE` 플래그를 `useImeBridge.ts` 안에 뒀다. `"composition"`(B안)으로 올리면
  `{t:'ime',kind:'set'}` 중계 경로가 켜지지만, **Runner 의 `setComposition` 이 아직 에러를
  던지므로** 지금 올리면 안 된다. 그 사실을 파일 주석에 명시했다.

### 구현 중 발견해서 보완한 것 — 무조합 텍스트 삽입 경로

처음 구현은 `compositionend` 만 들었다. 그러면 **붙여넣기나 `Input.insertText` 처럼
조합 이벤트 없이 글자가 통째로 들어오는 경우 아무것도 전송되지 않는다.**
`input` 이벤트에서 `inputType !== "insertCompositionText"` 이고 키 경로로 이미 보내지 않은
데이터만 골라 `ime.commit` 으로 보내는 보완 경로를 넣었다(중복 전송 방지 포함).
이 덕에 위 표의 세 번째 행이 통과한다.

### 1. ★ `react-hooks` 규칙이 **렌더 중 ref 쓰기를 전부 막는다** (Gen-Phase 11 이 반드시 밟는다)

이 레포의 eslint 설정은 React Compiler 계열 규칙이 켜져 있다. 다음이 **전부 에러**다.

```ts
const ref = useRef(value);
ref.current = value;              // ❌ react-hooks/refs  "Cannot update ref during render"

useEffect(() => { setX(v); }, []) // ❌ react-hooks/set-state-in-effect (effect 본문의 동기 setState)

<input ref={bridge.inputRef} />   // ❌ 훅이 돌려준 **객체의 ref 필드**를 렌더에서 꺼내는 것도 걸린다
```

해결책 3가지(이번에 실제로 쓴 것):

| 상황 | 해결 |
|---|---|
| 최신 값을 이벤트 핸들러에서 보고 싶다 | **의존성으로 받아라.** DOM 에 붙는 핸들러는 정체성이 바뀌어도 리바인딩뿐이다 |
| 정체성을 꼭 고정해야 한다(WS effect 등) | ref 쓰기를 **`useEffect` 안**에서 한다 |
| 훅이 ref 를 밖으로 내보내야 한다 | **콜백 ref 를 내보내라** (`attachInput: (el) => void`). ref 객체를 내보내면 소비처에서 걸린다 |
| effect 시작 시 상태를 초기화하고 싶다 | **파생으로 표현하라.** 이번엔 `{url, status}` 를 같이 들고 `url !== wsUrl` 이면 `connecting` 으로 **계산**했다 |

SSE(`lib/sse.ts`)를 붙이는 Gen-Phase 11 이 정확히 같은 모양(외부 구독 + 상태)이라 그대로 해당된다.

  나중 탭만 프레임을 받는다. MVP 전제상 문제없지만 화면 공유 기능이 생기면 여기가 먼저 걸린다.
- **새로고침하면 진행 중이던 녹화 세션을 이어받지 못한다.** 브라우저는 유휴 타임아웃까지
  살아 있지만(04-gen-7 이슈 5번) 클라이언트가 `sessionId`/토큰을 어디에도 남기지 않는다.
  이어받으려면 `sessionStorage` 에 `{sessionId, wsUrl}` 을 두고 복귀 시 재접속해야 한다
  (토큰 TTL 10분이 먼저 끝날 수 있다).
- **`{t:'nav'}` 를 HUD 에 문자열로만 쓴다.** 주소창 UI 를 만들지 않았다. 원격에서 직접
  주소를 바꾸는 수단이 없다(시작 URL 만 지정 가능).

## 이슈 / 결정사항

### 1. ★ 순서 변경이 Locator 를 조용히 열화시킬 뻔했다

가장 위험했던 지점이다. 설계대로 "화면의 스텝 배열을 `PUT` 한다"를 그대로 구현했다면,
화면이 가진 것은 **css 가 제거된 공개형**이므로 순서만 바꿔도 `test_steps.target_json` 에서
css fallback 이 사라진다. 재생은 당장은 되지만 **role/label 이 흔들리는 화면에서 조용히 깨진다.**
→ 전송 직전에 `?advanced=1` 로 원본을 다시 읽어 그것으로 PUT 한다.
**재생 5/5 통과 + 고급 설정에 `css · #username` 이 여전히 보이는 것**이 지워지지 않았다는 증거다.

삭제는 `DELETE /api/steps/:id` 를 쓴다(서버가 뒤 스텝 `sequence` 를 당겨 준다).
"순서변경·삭제를 한 요청으로"라는 지시와 다르지만, **삭제하려고 css 를 한 바퀴 돌리는 것보다
전용 엔드포인트가 안전하다.** 순서 변경은 지시대로 `PUT` 전량 치환이다.

### 2. 인스펙터의 "동작" select 는 검증 3종만으로는 성립하지 않는다

시안의 선택된 스텝은 검증 스텝(`대시보드가 표시되는지 확인`)이라 3종만 있으면 된다.
그런데 **녹화가 만드는 스텝은 대부분 클릭·입력**이다. 그 스텝을 선택했을 때 3종만 보이면
값이 없는 select 가 되어 **열자마자 동작이 바뀐 것처럼** 보인다.
→ 검증이 아닌 스텝에는 `입력 — 녹화된 동작` 줄을 맨 앞에 남긴다. 3종 문구는 시안 그대로다.

### 3. 숨은 IME 입력란은 **비밀번호가 지나가는 통로**다

테스터가 원격 비밀번호 칸에 타이핑하면 그 글자가 **우리 DOM 의 숨은 input 에도** 들어온다.
원격 녹화(`injected.ts`)가 아무리 비밀번호를 안 읽어도 여기가 새 유출 경로가 된다.
→ 조합이 끝나거나(`compositionend`) 조합 없는 입력이 끝난 직후(`input`) **값을 즉시 비운다.**
`autoComplete="off"`·`spellCheck={false}`·`aria-hidden` 도 같이 건다.
실측에서 `hunter2` 타이핑 직후 `imeInputValue` 가 **빈 문자열**임을 확인했다.

### 4. Runner 미기동을 화면에서 먼저 막는다

`POST /api/scenarios/:id/recordings` 는 **Runner 가 죽어 있어도 201 을 준다**(API 는 세션 레코드와
토큰만 만든다). 그대로 두면 테스터 눈에는 "검은 화면에서 아무 일도 안 일어남"으로 보인다.
→ `GET /api/health` 의 `runner` 를 15초마다 보고, `down` 이면 amber notice + 시작 버튼 잠금.
`HealthResponse` 는 contracts 에 없는 운영 진단 응답이라(health.service 주석) `useHealth.ts` 에서
좁게 선언했다. **도메인 계약을 web 이 재정의한 것이 아니다.**

### 5. 유휴 타임아웃 keepalive 로 `resize` 를 쓴다

유휴 5분은 "화면을 보고만 있는" 테스터를 끊는다. `session.ts` 는 **어떤 C→S 메시지든**
시계를 리셋하는데(`dispatch` → `touch()`), `resize` 는 **크기가 같으면 early-return** 하는
완전한 무해 메시지다. 마우스 이동을 쓰면 원격 커서가 움직여 hover 상태가 바뀐다.
→ 60초마다 **같은 크기의 `resize`** 를 보낸다.

### 6. 프레임 통계를 state 에 매 프레임 올리지 않는다

`rendered`/`fps` 를 그대로 `useState` 에 넣으면 **60fps 로 빌더 전체가 리렌더**된다
(스텝 카드·인스펙터까지). ref 에 쌓고 **500ms 마다만** state 로 올린다.
HUD 숫자는 그 주기로 갱신되고, 렌더 루프는 state 를 전혀 건드리지 않는다.

### 7. `getBoundingClientRect()` 를 이벤트마다 다시 잰다

캐시하면 스크롤·리사이즈·배율 변경 뒤 **조용히 틀린 좌표**를 보낸다(이 프로젝트에서 가장
비싼 종류의 버그다). 클릭당 1회 레이아웃 조회는 측정상 문제되지 않았다(오차 0.00px @100%).

### 8. 범위 준수

- **Gen-Phase 11 이후를 만들지 않았다.** `pages/runs` 없음, `RunDialog` 없음, `pages/suites` 없음.
  `/runs` · `/runs/:id` · `/suites` 는 여전히 `PagePlaceholder` 다.
- `apps/api` · `apps/runner` · `packages/db` · `docker-compose.yml` · `packages/contracts` 는
  `git status` 에 없다. Runner 는 **띄워서 쓰기만** 했고 fixture 는 서빙만 했다.
- Gen-Phase 8·9 산출물에서 **버그를 발견하지 못했다**(고친 것 0건).
  `globals.css` 는 `@utility` 1개 추가뿐이고 **토큰 값은 한 글자도 바꾸지 않았다.**
- 시드·시나리오는 전부 **공개 API 로** 만들었다(DB 직접 INSERT 없음).
- `git commit` 까지만 했고 **push 하지 않았다**.
