TestFlow · FR-002 녹화

같은 엔진, 다른 창.
1번과 3번의 진짜 차이

두 방식 모두 서버가 Playwright 브라우저를 띄우고, 거기서 일어난 클릭·입력을 잡아 스텝으로 바꿉니다. 수집 로직은 한 글자도 다르지 않습니다. 갈리는 건 단 하나 — 테스터가 어느 화면을 보고 조작하는가.

두 방식이 공유하는 부분

여기까지는 1번이든 3번이든 동일하게 만듭니다

01 브라우저 기동 서버가 Playwright로 Chromium을 띄우고 대상 URL을 엽니다.
02 행동 감지 페이지에 주입한 리스너가 클릭·입력·선택·이동을 잡아냅니다.
03 Locator 생성 role → label → text → test-id 순으로 가장 안정적인 식별자를 고릅니다.
04 스텝 적재 “아이디 입력” 같은 업무 문장으로 변환해 빌더에 실시간으로 쌓습니다.

그래서 나중에 방식을 바꿔도 이 4단계는 그대로 재사용됩니다. 1번으로 시작한 뒤 3번으로 올리는 건 화면 전달 계층만 교체하는 작업입니다.

결정을 가르는 질문은 하나입니다

TestFlow를 테스터들이 각자 PC에서 띄워 쓰나요, 아니면 사내 서버에 한 번 올려놓고 다 같이 접속하나요?

  • 각자 PC에서 실행 — 1번이 확실히 낫습니다. 브라우저 창이 바로 내 화면에 뜨고, 개발량도 훨씬 적습니다.
  • 사내 서버 한 대에 배포 — 1번은 결국 VNC를 붙이거나 3번으로 다시 만들어야 합니다. 처음부터 3번이 맞습니다.
  • 아직 모르겠다 — 1번으로 만들되 화면 전달 계층만 분리해두면, 나중에 3번으로 바꿀 때 수집 로직 4단계는 그대로 씁니다.
