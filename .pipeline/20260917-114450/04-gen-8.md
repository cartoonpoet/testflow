### ★ 발견: `@theme` 는 토큰을 **tree-shaking 한다** → `@theme static` 으로 바꿨다

처음엔 그냥 `@theme` 로 썼는데, 렌더 검증에서 **`:root` 에 토큰 71개가 아예 없었다.**
Tailwind 4 의 기본 `@theme` 은 *실제로 쓰인 유틸이 참조하는 변수만* `:root` 에 방출한다.
Gen-Phase 8 시점에는 테이블·notice·브라우저 목업 화면이 없으니 그 토큰들이 통째로 사라진 것이다.

그대로 뒀다면 Gen-Phase 9 가 `bg-[var(--color-notice)]` 나 `var(--color-table-head)` 를
참조하는 순간 **에러 없이 조용히 무효**가 됐을 것이다. 디자인 토큰은 "쓰이는 것"이 아니라
"계약"이므로 **`@theme static`** 으로 전환해 전량 방출시켰다.
비용은 CSS **21.1KB → 24.8KB (gzip 5.20 → 6.19KB)**. 이 정도면 계약을 지키는 값이 싸다.

> **Gen-Phase 9~11 주의**: 변수는 `static` 덕에 전부 살아 있지만,
> **유틸 클래스 자체는 여전히 on-demand** 다. `` className={`bg-${tone}`} `` 처럼
> **런타임에 조립한 클래스명은 생성되지 않는다.** 반드시 전체 클래스명을 소스에 리터럴로 써라
> (예: `const toneClass = { green: "text-success", red: "text-danger" }` — StatusDot 이 그 예시다).

## shadcn/ui + Tailwind 4.3 조합 결론 (04-gen-1 미검증 항목 해소)

**CLI 는 동작한다.** 다만 생성물을 그대로 쓰지는 않았다.

### 실측

```
$ npx --yes shadcn@latest add button --yes --overwrite
✔ Checking registry.   ✔ Installing dependencies.   ✔ Created 1 file: src/components/ui/button.tsx
```

- `components.json` 을 **css variables 모드**(`tailwind.config: ""`, `cssVariables: true`)로 손수
  써 두면 `init` 없이 `add` 가 바로 먹는다. Tailwind 4 는 JS config 가 없으므로
  `tailwind.config` 는 **빈 문자열**이 정답이다.
- yarn 4 워크스페이스를 인식해 `apps/web/package.json` + 루트 `yarn.lock` 을 정상 갱신했다.

### 막힌 곳 2건 (사실대로)

1. **CLI 가 `class-variance-authority` 를 설치하지 않는다.**
   생성된 `button.tsx` 는 `import { cva } from "class-variance-authority"` 를 쓰는데
   설치한 건 `cn`, `radix-ui` 둘뿐이었다. 그대로 두면 typecheck 가 깨진다.
   → `class-variance-authority@0.7.1` 을 직접 추가했다.
2. **CLI 가 버전을 `^` 레인지로 박는다**(`cn: ^0.3.0`, `radix-ui: ^1.6.7`).
   이 레포는 04-gen-1 부터 **정확한 핀** 규약이라 전부 고정 버전으로 고쳐 썼다.

### 생성물을 채택하지 않은 이유

shadcn 기본 `button.tsx` 의 variant 는 `bg-primary` / `text-primary-foreground` /
`focus-visible:ring-ring` 등 **shadcn 자체 시맨틱 토큰 위에 서 있고**, 반경·padding·min-height도
전부 shadcn 값(`rounded-md`, `h-9`)이다. 시안 스펙(반경 10px, padding 9px 13px, min-height 38px,
font-weight 700)으로 맞추려면 **variant 문자열을 전부 다시 쓰는 것**과 같다.

→ **구조는 채택하고 값은 시안으로 갈아끼웠다.** `cva` + `Slot`(asChild) + `cn` + `data-slot`
패턴을 그대로 유지했으므로 앞으로 CLI 로 추가하는 컴포넌트와 이질감이 없다.
추가로 **L3 호환 별칭 레이어**(`--color-primary: var(--color-brand)` 등 18개)를 `@theme` 에 깔아
**앞으로 CLI 가 찍어 내는 컴포넌트는 손대지 않아도 시안 팔레트로 렌더된다.**

### 결론

> Tailwind 4.3 + shadcn CLI 조합은 **사용 가능**. 단 ① cva 를 직접 설치하고
> ② 생성물의 variant 는 시안 스펙으로 덮어써야 하며 ③ 버전 핀을 손으로 고쳐야 한다.
> 폴더 구조는 이 레포 관행(1폴더 1컴포넌트 + barrel)으로 접어 넣었으므로,
> 앞으로 `add` 한 파일은 `ui/<name>.tsx` 로 평평하게 떨어진다 → 폴더로 옮기고 barrel 에 등록할 것.

## 폰트 조달 결정

**로컬 번들 — `apps/web/public/fonts/PretendardVariable.woff2` (2.0MB, v1.3.9) 를 커밋했다.**

| 후보 | 판정 |
|---|---|
| CDN(jsdelivr 등) | ❌ **사내망 배포**라 외부 CDN 이 막힐 수 있다. 막히면 폰트가 통째로 죽는다 |
| `pretendard` npm 패키지 의존 | ❌ unpacked **97MB / 1,826 파일**. 전 웨이트·전 포맷을 다 담고 있어 과하다 |
| 시스템 폰트 폴백만 | ❌ **가변 웨이트가 죽는다**(아래) |
| **가변 woff2 1개 자체 호스팅** | ✅ 채택 |

**가변 폰트가 선택이 아니라 필수인 이유**: 시안이 `font-weight: 750` / `850` 을 쓴다
(`.nav-item.active` 750, `.logo` 850, `.record-badge` 850, `.field label` 750 …).
static 파일(400/500/700/900)만 넣으면 브라우저가 750→700, 850→900 으로 **반올림**해
시안의 한국어 UI 웨이트 감각이 사라진다. `font-weight: 45 920` 범위의 가변 파일이라야
750/850 이 실제로 그 굵기로 렌더된다 — 렌더 검증에서 `font-750` → `fontWeight=750`,
`font-850` → `fontWeight=850` 을 실측으로 확인했다.

`@font-face` 는 **`local()` 을 먼저** 둔다.

```css
src: local("Pretendard Variable"), local("Pretendard"),
     url("/fonts/PretendardVariable.woff2") format("woff2-variations");
```

사내 PC 에 Pretendard 가 이미 깔려 있으면 **네트워크 요청 자체가 없고**, 없으면 2MB 를 1회
받아 캐시한다(사내 LAN 이라 체감 없음). `font-display: swap` 으로 폰트 대기 중 백지를 막았다.
폰트 family 이름을 `"Pretendard"` 로 맞춰 **시안의 폰트 스택 문자열을 한 글자도 바꾸지 않았다**
(`"Pretendard","SUIT","Apple SD Gothic Neo",sans-serif`).

`.gitattributes` 에 `*.woff2 binary` 가 이미 있어 CRLF 변환 위험은 없다(Gen-Phase 1 산출물).

### 5. `lib/sse.ts` 사용법 (Gen-Phase 11 핵심)

```ts
const stream = subscribeRunEvents({
  runId,
  onEvent: (e) => { /* e 는 RunEvent discriminated union, 이미 파싱됨 */ },
  onDesync: () => queryClient.invalidateQueries({ queryKey: queryKeys.run(runId) }),
```

## 이슈 / 결정사항

### 1. ★ `@theme` → `@theme static` (위에서 상술)

토큰 tree-shaking 을 렌더 검증으로 잡아냈다. 디자인 토큰은 계약이므로 전량 방출이 맞다.
비용 gzip +1KB.

### 2. 사이드바 하단 "사용자 정보" 를 어떻게 처리했나 (비회원제)

시안은 아바타 + `손준호` / `테스트 관리자` 다. **비회원제라 계정이 없으므로 레이아웃만 남기고
내용을 고정 텍스트로 바꿨다** — 아바타 이니셜 `공`(시안 색 `#e8c471`/`#4b3503` 유지),
제목 `공용 워크스페이스`, 부제 `비회원 공용 접속`(title 속성에 "로그인 없이 모두가 함께 사용합니다").

**가짜 사람 이름을 넣지 않은 것이 핵심이다.** 시안대로 `손준호`를 박아 두면 테스터가
"내 계정으로 로그인돼 있다"고 오해하고, 나중에 회원제를 도입할 때 그 오해가 버그 리포트로 돌아온다.
프로젝트 스위처도 같은 이유로 `disabled` 다(MVP 는 단일 프로젝트).

### 3. MANAGE 그룹 비활성 처리 방식

실행 환경·테스트 데이터·프로젝트 설정은 **라우트를 만들지 않고** `NavEntry.enabled: false` 로
`<button disabled>` 렌더 + `opacity-40` + `title="MVP 범위에 포함되지 않은 화면입니다"`.
메뉴를 **지우지 않은 이유**: 시안의 그룹 구조(4+4)를 유지하면서 "없는 기능"과 "아직인 기능"을
구분해 보여 주기 위함이다. 테스트 스위트는 MVP 포함이라 **활성**이다.

### 4. Select 를 Radix 가 아니라 네이티브 `<select>` 로 했다

시안의 `.filter` / `.field select` 는 **네이티브 select 의 외형 그대로**다
(커스텀 드롭다운 패널·검색·멀티셀렉트가 없다). Radix Select 를 쓰면 포털·애니메이션·
`prefers-reduced-motion` 처리가 따라붙는데 시안이 요구하지 않는 복잡도다.
접근성도 네이티브가 기본적으로 낫다. 모바일에서도 OS 기본 피커가 뜬다.
`variant="field|filter"` 두 형태만 두어 툴바/인스펙터 양쪽을 커버했다.

### 5. `baseUrl` 을 tsconfig 에서 뺐다 (TS 6 deprecation)

처음엔 `baseUrl: "."` + `paths` 로 썼는데 **TS 6.0.3 이 하드 에러**를 낸다
(`TS5101: Option 'baseUrl' is deprecated and will stop functioning in TypeScript 7.0`).
`ignoreDeprecations` 로 억누르지 않고 **`baseUrl` 을 제거**했다 —
TS 5 이후 `paths` 는 tsconfig 파일 위치를 기준으로 해석되므로 필요 없다.
04-gen-1 의 "TS 7 재승급" 시나리오에도 이 편이 안전하다.

### 6. `tf-*` 레이아웃 유틸을 `@utility` 로 만든 이유

시안의 2단 그리드 4종은 **열 비율만 다르고 1050px 에서 접히는 규칙이 같다.**
Gen-Phase 9~11 이 매번 `grid-cols-[minmax(0,1.45fr)_minmax(320px,.75fr)] max-compact:grid-cols-1`
를 손으로 다시 쓰면 오타 한 글자에 레이아웃이 어긋난다. Tailwind 4 의 `@utility` 는 공식 확장
지점이므로 "인라인 CSS 금지" 규율에 어긋나지 않는다.
사용처가 없으면 생성되지 않으므로 **`@source inline(...)`** 으로 강제 포함시켰고,
덕분에 이번 Phase 에서 1050px 브레이크포인트를 실제로 측정할 수 있었다.

### 7. 범위 준수

- **화면 페이지를 만들지 않았다.** `pages/dashboard`·`pages/scenarios`·`pages/runs`·`pages/suites`
  디렉토리가 **없다**. `features/recorder` 도 **없다**.
  라우터 골격만 두고 내용은 `PagePlaceholder` 한 개로 통일했다(허용 범위).
- **손대지 말라는 것을 손대지 않았다**: `apps/api/*`, `apps/runner/*`, `packages/db/*`,
  `docker-compose.yml`, `packages/contracts` 스키마 — `git status` 에 전부 없다.
- `@testflow/contracts` 는 **읽기만** 했다(`RunEventSchema`, `SSE_EVENT_NAMES`, `RunEvent`).
  web 에서 타입을 재정의한 곳은 없다. **`@testflow/db` 는 import 하지 않았다.**
- `git commit` 까지만 했고 **push 하지 않았다**.

### 8. 남은 리스크 / 다음 Phase 가 결정할 것

- **탑바 액션 주입 경로 미결** (위 "7. 라우터" 마지막 문단). Gen-Phase 9 에서 정해야 한다.
- **`lib/api.ts`·`lib/sse.ts` 실동작 미검증.** 첫 화면이 붙는 Gen-Phase 9 에서
  `GET /api/dashboard/summary` 왕복을 **가장 먼저** 확인하라 — CORS·프록시 설정이
  여기서 처음 드러난다(`vite.config.ts` 에 `server.proxy` 가 아직 없다).
- **JS 번들 377KB(gzip 121KB)** 는 react-router + react-query + radix 합산이다.
  화면이 붙으면 더 커진다. 사내망이라 당장 문제는 아니지만 Gen-Phase 12 에서
  라우트 단위 code-splitting 을 검토할 여지가 있다.
- **Pretendard 2MB** 는 최초 1회 비용이다. 사내 PC 에 폰트가 깔려 있으면 `local()` 로 생략된다.
  실사용에서 느리면 `pyftsubset` 으로 KS X 1001 범위 서브셋을 만들어 교체하면 된다
  (이번엔 개발 머신에 fonttools 가 없어 못 했다).
