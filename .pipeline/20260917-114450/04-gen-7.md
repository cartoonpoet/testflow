### Locator 우선순위 — ✅ 실측대로 나온다

- `#login-submit`(button) → **role** (`getByRole('button',{name:'로그인'})`) — 우선순위 1

- css 는 **언제나 마지막**이고 API 기본 응답에서는 제거된다(`?advanced=1` 에서만 보인다).

## 고유성 검증 동작 확인 ★

검증 방식이 자기충족적이지 않다는 근거 — `injected.spec.ts` 는 injected 가 만든 후보를

후보를 만드는 쪽(페이지 안 자체 구현)과 푸는 쪽(Playwright)은 **서로 다른 구현**이므로,
둘이 어긋나면 이 테스트가 잡는다. 8개 케이스 전부 `count() === 1`.

```
✓ "확인" 버튼 3개 — primary 가 서로 다르고 각각 정확히 1개에 매칭된다
✓ "삭제" 버튼 3개 — 구별 속성이 없으면 nth 로 좁혀 유일해진다
✓ role 이 잡히는 버튼은 role 이 primary 다 (우선순위 1)
✓ label 로 이름이 붙은 입력란 — role 이 먼저 잡히고 label 은 fallback 으로 남는다
✓ ★ password 입력란은 role 후보를 만들지 않는다
✓ ★ 스냅샷에 value 속성을 담지 않는다 (비밀번호 유출 경로 차단)
✓ fallback 체인이 순위 배열로 저장되고 css 는 언제나 마지막이다
```

### ★ `within` 대신 `nth` 를 쓴 이유 (계획서와 다른 선택 — 확인 필요)

03-phases Task 7.4 는 "조상 컨테이너로 범위를 좁히거나(`within`) `nth` 로 좁히거나"라고 적었다.
**`within` 은 쓰지 않았다.** `LocatorCandidateSchema` 에 `within` 필드가 없고, 소비하는 쪽인
Gen-Phase 6 의 `locator.ts` 에도 **범위(scope) 개념이 없다.** contracts 에 필드만 추가하면

(`candidate.nth !== undefined` 분기 — "여러 개 중 n 번째"로 해석하고 존재만 확인한다).
`within` 이 필요하면 **contracts + `locator.ts` 를 같이 고치는 별도 작업**으로 가야 한다.

### 계획과 다르게 한 것 / 사실 기록

- **`injected.ts` 를 "모듈"이 아니라 "스크립트"로 emit 한다.** `addInitScript({path})` 는 파일을
  페이지에서 그대로 평가하므로 ESM `export` 가 한 줄이라도 있으면 SyntaxError 가 난다.
  → 그 파일에는 import/export 를 두지 않고 `tsconfig.injected.json` 에서 `isolatedModules` 를 끈다
  (켜져 있으면 TS1208 로 글로벌 스크립트를 거부한다). 산출물에 `export` 가 없음을 grep 으로 확인했다.
  대가는 **타입을 공유하지 못하는 것** — `RecordedAction` 이 `injected.ts` 와 `step-mapper.ts` 에
  두 벌 있다. 양쪽 주석에 "1:1 이므로 같이 고쳐라"를 명시했다.

  리스너로 잡는다. 다만 `Tab` 은 **포커스 이동일 뿐**이라 재생에 필요 없고 스텝만 늘린다 →
  `Tab` 은 **대기 중 입력을 확정(flush)** 하는 데만 쓴다. `Enter` 는 폼을 보내므로 `press` 스텝으로 남긴다.
- **클릭 직후 2초 이내의 네비게이션은 `goto` 스텝을 만들지 않는다.** 만들면 재생 시

- **텍스트 입력란을 눌러 포커스를 옮기는 클릭은 스텝이 아니다.** 뒤따르는 `fill` 이 대신한다.
  (그래서 실측 7스텝에 "아이디 칸 클릭"이 없다.) 단 그 클릭이 버튼/링크 안이면 클릭 스텝을 남긴다.
- **체크박스/라디오는 `click` 이 아니라 `change` 에서 `check`/`uncheck` 로만 만든다.** 둘 다 만들면
  같은 행동이 스텝 2개가 된다.
- **fps 스로틀 대조군을 새로 측정했다**(계획에 없던 작업). PoC-1 과 fixture 가 달라 숫자를 직접
  비교하면 틀린 결론이 나온다. 같은 fixture 에서 `RECORD_MAX_FPS=0` 으로 한 번 더 쟀다.
- **`within` 을 구현하지 않았다.** 사유는 위 "고유성 검증" 절 참조 — `locator.ts` 가 소비하지
  않는 필드를 만들면 재생이 조용히 깨진다.
- **한글 IME 는 손대지 않았다.** `insertText`(A안) 경로만 쓰고 `setComposition`/`commitComposition`
  은 여전히 호출 시 에러를 던지는 상태다(PoC-2 / Gen-Phase 12).

## 이슈 / 결정사항

### 1. ★ 초안을 "종료 신호를 받고 나서" 저장하면 **경합에 져서 통째로 사라진다**

`POST /api/recordings/:id/stop` 의 순서는 이렇다(`recordings.service.ts`, Gen-Phase 5):

```
① session = SELECT recording_sessions            ← draft_steps 를 **여기서** 읽는다
② INSERT test_steps (append)
③ UPDATE status='stopped', draft_steps=[]
④ PUBLISH rec:<id>:control {t:'stop'}            ← Runner 는 **이제서야** 신호를 받는다
```

Runner 가 `④` 를 받고 flush 하면 **①은 이미 지나갔다.** 초안이 하나도 반영되지 않는다.
→ 그래서 세션은 **초안이 생길 때마다(150ms 합치기 창 뒤) 즉시 DB 에 쓴다.**
"세션이 끊겨도 테스터 작업이 날아가지 않게"(02-context 설계 주석)는 그 **부수 효과**이지
주된 이유가 아니다. 이 순서 의존은 `session.ts` 상단 주석에 명시했다.
**API 쪽을 고치지 않고 Runner 쪽에서 해결했다** — Gen-Phase 5 산출물 무수정 제약 때문이다.

### 2. `input[type=password]` 의 role 후보를 **의도적으로 만들지 않는다**

HTML-AAM 상 password 입력에는 대응 ARIA role 이 없어 Playwright 의 `getByRole('textbox')` 에
**잡히지 않는다.** 순진하게 `textbox` 후보를 만들면 페이지 안에서는(우리 자체 매칭) 1개로 보이는데
재생 시 Playwright 가 0개를 반환해 fallback 으로 떨어진다 — 가장 찾기 어려운 종류의 버그다.
`computeRole()` 에서 `password` 를 제외했고, `injected.spec.ts` 가 "password 의 후보 체인에
role 이 없다"를 직접 검사한다.

### 3. 자체 매칭 규칙은 Playwright 의 **근사치**다 (이중 방어로 감당한다)

`injected.ts` 의 role/accessible-name 계산은 ARIA 스펙 전체가 아니라 실무에 필요한 범위의
근사 구현이다. 틀리면 **후보가 하나 탈락할 뿐 재생이 깨지지는 않는다** — 재생 시점에도
`locator.ts` 가 "정확히 1개"를 다시 확인하고 안 맞으면 다음 후보로 내려가기 때문이다.
그리고 `injected.spec.ts` 가 **두 구현의 판정이 일치하는지**를 매 테스트마다 대조한다.
사내 실화면에서 어긋나는 사례가 나오면 그때 `computeRole`/`accessibleName` 을 보강한다.

### 4. WS 는 세션당 **클라이언트 1개**만 전제한다

`session.attach(sink)` 가 마지막 것 하나만 들고 있다. 두 번째 클라이언트가 붙으면 첫 번째는
프레임을 못 받는다(조용히). MVP 는 "테스터 1명이 자기 세션을 본다"가 전제라 문제되지 않지만,
**화면 공유/관전 기능이 생기면 여기가 먼저 걸린다.** 다중 sink 로 바꾸는 것은 `session.ts`
한 파일 안에서 끝난다.

### 5. WS 가 끊겨도 브라우저를 즉시 접지 않는다

새로고침 한 번에 녹화 중이던 브라우저가 죽으면 테스터가 처음부터 다시 해야 한다.
`close` 에서는 sink 만 떼고, **유휴 타임아웃이 최종 방어선**이다(04-gen-5 결정 3번과 같은 철학).
`stop`/`DELETE` 는 제어 채널로 즉시 접는다.

### 6. 화면 전달 계층 2개 파일은 **열어서 읽고 import 만** 했다

`screencast.ts`·`input-bridge.ts` 를 한 글자도 고치지 않았다. `resize` 를 세션이 처리하는 것도
그 제약을 지키기 위해서다(04-gen-3 이슈 5번). 1번(별도 창) 방식으로 후퇴하더라도
**`injected.ts`·`step-mapper.ts` 는 그대로 유효**하고, `session.ts` 에서 교체되는 것은
`startScreencast`/`createInputBridge` 두 호출뿐이다.
