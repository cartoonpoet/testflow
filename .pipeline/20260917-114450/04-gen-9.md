### 원칙 3가지

1. **패널 단위로 처리한다.** 페이지 전체를 한 덩어리로 묶지 않았다.
   `/runs` 하나가 죽어도 지표·준비도는 멀쩡히 보인다(`05-dashboard-error.png` 반대 케이스로 확인).

   자리를 잡아 두면 데이터 도착 시 화면이 튀지 않는다. 스켈레톤의 열 수·패딩·높이를
   실제 표/카드와 동일하게 맞췄다(`06-dashboard-loading.png`, 스켈레톤 45개).
3. **에러에는 반드시 재시도 버튼.** react-query `refetch` 를 그대로 물린다.

### 실패했다가 고친 것 / 미검증 (사실대로)

1. **첫 측정에서 `mini-status` 가 12px 로 나왔다** → StatusDot 버그였다(이슈 1번). 고치고 10px 확인.
2. **첫 측정에서 503 에러 화면이 20초 동안 안 떴다** → 무한 스켈레톤 버그였다(이슈 2번). 고치고 확인.
3. **측정 스크립트 자체의 버그 2건** — `Number("34px")`→NaN(→`parseFloat`),
   `rounded-full` 의 computed 값이 `50%` 가 아니라 `calc(infinity*1px)` 인 것(→임계값 비교).
   둘 다 **측정 방식의 오류**였지 화면의 오류가 아니다.
4. **`lib/sse.ts` 는 여전히 미검증이다.** 화면 1·2 가 SSE 를 안 쓴다. Gen-Phase 11 몫.
5. **접근성 자동 검사(axe)는 돌리지 않았다.** 범위 밖. 다만 행 클릭을 `<button>`/`role="link"`+
   키보드 핸들러로, 진행바를 `role="progressbar"` 로, 에러를 `role="alert"` 로 만들어 뒀다.
6. **검증 스크립트(`tf-verify9.mjs`)는 커밋하지 않았다** — Gen-Phase 8 과 같은 판단이다
   (`playwright` 해석을 위해 루트에 둬야 하는데 그러면 lint 범위가 애매해진다).
   재현이 필요하면 위 측정표가 그대로 명세다. 스크린샷은 `/tmp/tf-verify9/`.
7. **페이지네이션은 UI 만 있고 2페이지를 실측하지 못했다.** 시나리오가 13건이라 `size=20`
   한 페이지에 다 들어간다. `total/page/size` 값이 올바르게 내려오는 것까지는 확인했다.

## 다음 Gen-Phase 에 전달할 사항

### 1. ★ `cn()` 이 토큰 기반 `text-*` 를 **조용히 지운다**

가장 중요한 전달 사항이다. Gen-Phase 10·11 에서 반드시 밟게 될 지뢰다.

```tsx
cn("text-th", "text-success")        // ❌ text-th 가 사라진다 (둘 다 "색"으로 분류됨)
cn("text-[length:var(--text-th)]", "text-success")   // ✅
className="text-th text-success"     // ✅ cn 을 안 거치면 문제없다
```

`cn`(tailwind-merge)은 `text-*` 가 글자 크기인지 색인지를 **이름만 보고** 판정한다.
`th`/`td`/`metric`/`panel-title` 같은 커스텀 토큰 이름은 t-shirt 사이즈도 임의값도 아니라
**전부 "색"으로 분류**되고, 뒤에 오는 색 클래스와 같은 그룹으로 묶여 제거된다.
**에러가 나지 않고 조용히 크기만 틀린다** — 실측하지 않으면 모른다.

- `text-metric` / `text-panel-title` / `text-td` / `text-label` / `text-nav-label` 전부 해당.
- **`cn` 을 거치면서 색 클래스와 같이 쓸 때만** 문제다. 평범한 문자열 className 은 안전하다.
- 안전한 우회: `text-[length:var(--text-metric)]` 처럼 `length:` 힌트를 붙인다. 토큰은 그대로 쓴다.

## 이슈 / 결정사항

### 1. ★ Gen-Phase 8 프리미티브 버그를 하나 고쳤다 — `StatusDot`

**증상**: 시안 `.mini-status` 는 10px 인데 테이블 안에서 **12px(td 상속)로 렌더**됐다.
**원인**: `cn("… text-th font-750 tracking-normal", toneClass[tone])` 에서
tailwind-merge 가 `text-th` 와 `text-success` 를 **같은 "색" 그룹**으로 보고 `text-th` 를 지웠다.
**고침**: `text-[length:var(--text-th)]` 로 바꿔 글자 크기로 분류되게 했다(토큰은 그대로).
`tracking-normal` 도 함께 뺐다 — 시안 `.mini-status` 에는 letter-spacing 지정이 없어
body 의 `-.018em` 을 상속하는 게 맞다(`text-th` 가 딸려 오게 하던 `.04em` 을 지우려던 클래스였다).

> Gen-Phase 8 이 "194/194 통과"라고 한 건 **StatusDot 을 실제 화면에 렌더해 본 적이 없어서**다.
> 프리미티브는 **쓰이는 자리에서** 재야 한다는 교훈. 위 "전달할 사항 1번"에 일반화해 적어 뒀다.

### 2. ★ 무한 로딩 버그 — 503 을 실제로 만들어 보고서야 드러났다

**증상**: API 를 503 으로 막았는데 **에러 화면이 20초가 지나도 안 떴다.** 스켈레톤만 계속 돌았다.
**원인**: 모든 쿼리가 `enabled: projectId !== undefined` 인데, `GET /api/projects` 자체가 실패하면
`projectId` 가 영원히 `undefined` 라 **하위 쿼리가 시작조차 하지 않는다.**
react-query 는 시작하지 않은 쿼리를 영원히 `isPending` 으로 둔다 — 화면은 "로딩 중"에서 멈춘다.
**고침**: `components/ProjectGate` 를 만들어 프로젝트 조회의 실패·빈 결과를 **화면 단위로** 처리.
대시보드·시나리오 목록 둘 다 본문을 이걸로 감쌌다.

> **`enabled` 로 의존 쿼리를 막을 때는 선행 쿼리의 실패 경로를 반드시 같이 설계해야 한다.**
> Gen-Phase 10·11 도 `projectId`/`scenarioId` 로 같은 구조를 만들 텐데 그때마다 해당된다.
> 지시받은 "에러는 API 를 끄거나 잘못된 경로로 유도해 **실제로** 만들어라"가 아니었으면 못 잡았다.

### 3. `/api` 프록시를 vite 에 넣었다 (CORS 를 만들지 않는 쪽으로)

04-gen-8 이 "CORS·프록시가 Gen-Phase 9 에서 처음 드러난다"고 예고한 지점이다.
선택지는 ① `VITE_API_BASE_URL=http://127.0.0.1:4000/api` + CORS 허용, ② vite 프록시였다.
**②를 골랐다** — `lib/api.ts` 의 베이스가 `/api` 이고 **운영(nginx 동일 오리진)이 바로 그 모양**이다.
①로 하면 개발과 운영의 네트워크 모양이 달라져 "개발에선 되는데 배포하면 안 되는" 부류의 차이가 생긴다.
`server` 와 `preview` 양쪽에 걸었다(렌더 검증을 preview 로 하기 때문).
`process.env` 는 읽지 않았다 — 이 tsconfig 는 `types:["vite/client"]` 뿐이라 Node 전역이 없다.

### 4. 인라인 CSS 금지 규율을 지키면서 "데이터로 정해지는 폭"을 그리는 법

진행바 폭은 상수가 아니라 데이터(`percent`)다. `style={{width: …}}` 로 쓰면 규율 위반이다.
→ `@utility tf-bar-fill` 에 높이·색·반경을 전부 두고, 컴포넌트는 **값 하나만** 넘긴다:
`style={{"--tf-bar-width": toBarWidth(percent)}}`.
**스타일은 CSS 에 남고 컴포넌트는 데이터만 넘긴다**는 점에서 규율의 취지에 맞는다.
레포 전체에서 `style={{` 는 이 한 곳뿐이다.

### 5. 지표 `delta` 에 없는 숫자를 만들지 않았다

시안은 "지난주 대비 +2.4%", "18초 단축", "성공 43 · 실패 5" 를 보여 준다.
`DashboardSummary` 에는 **4개 필드뿐**이고 이전 기간 값이 없다.
`todayRuns × successRate` 로 성공/실패 건수를 역산할 수는 있지만,
`successRate` 의 분모는 **종료된 run** 이고 `todayRuns` 는 **큐에 들어간 run** 이라
(04-gen-5 dashboard.service 주석) **두 수의 곱은 틀린 숫자다.**
화면은 시안과 같아 보이는데 숫자만 거짓인 상태가 가장 나쁘다.
→ delta 자리에 **집계 기준**을 적었다("오늘 00시 이후 요청 기준" / "종료된 실행 기준" /
"완료된 실행의 평균"). 자리는 채우고 거짓말은 안 한다.
단 "자동화 시나리오"만은 `readiness.totalScenarios` 라는 **실제 값**이 있어
`발행됨 7 / 전체 13` 으로 시안의 `발행됨 118` 과 같은 성격을 재현했다.

### 6. 검색 input 에 `ui/Input` 프리미티브를 쓰지 않았다

시안 `.search` 는 **테두리가 바깥 래퍼에 있고 input 은 투명·무테**다(`⌕` 아이콘과 한 상자).
`Input` 프리미티브는 자기 테두리와 focus 링을 갖고 있어 겹친다.
→ 래퍼에 `focus-within:border-brand focus-within:shadow-focus-ring` 를 줘
**focus 링의 시각적 계약은 동일**하게 맞추고 input 자체는 무테로 뒀다.
Select 는 지시대로 네이티브 `<select>` 기반 `ui/Select variant="filter"` 를 그대로 썼다.

### 7. 컴포넌트 배치

03-phases 는 `components/MetricCard.tsx` 처럼 평평한 경로를 적었지만,
레포 관행(1폴더 1컴포넌트 + barrel)에 맞춰 `components/MetricCard/{MetricCard.tsx,index.ts}` 로 접었다.
`components/index.ts` 를 새로 만들어 `MetricCard`/`RunRow`/`NoticeBox`/`ProjectGate` 를 재노출한다.
`ui/` 는 시안 프리미티브, `components/` 는 시안 화면 조각, `layout/` 은 셸 — 3단 구분이다.
`Skeleton`/`StateView`/`PageHead` 는 04-gen-8 지시("새 컴포넌트는 `ui/<Name>/` 에 만들고
`ui/index.ts` 에 등록")대로 `ui/` 에 넣었다.
